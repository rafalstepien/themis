The plan
1. Collapse to a single protocol/client.

Remove OpenAIClient. OpenAICompatibleClient becomes the only concrete client. Decide the base-class fate above (keep-with-comment or inline).

Commit: refactor(llm): route OpenAI through the compatible client, drop Responses client
2. Make the discriminator honest.

Reduce LLMProvider to what has a client: effectively just OPENAI_COMPATIBLE. A one-value enum looks odd but it's truthful and it's your labelled extension point — the place protocol #2 will be added.

Commit: refactor(config): reduce LLMProvider to backed protocols
3. Move vendor names to clearly-labelled convenience sugar.

openai, gemini, anthropic become shortcuts that desugar (in a model_validator(mode="before")) to openai_compatible + a default base_url. The _DEFAULT_BASE_URLS / shortcut map is your "convenience URLs" idea — keep it, but name it as sugar, not protocol. Add openai → https://api.openai.com/v1 to that map so provider: openai keeps working.

Commit: feat(config): expand vendor shortcuts to openai_compatible + default base_url
4. Simplify the resolver.

After step 3, base_url is always concrete by the time the resolver runs, so resolve_base_url, the None-tripwire, and the vendor cases all disappear. Resolver collapses to: test-mode → mock; everything else → compat client.

Commit: refactor(llm): simplify resolver to a single dispatch
5. Reconcile token policy with the desugaring.

This is the interaction to get right, and it's easy to miss: after desugaring, every provider reads as openai_compatible, so you can no longer tell "cloud shortcut (needs key)" from "raw self-host (keyless OK)." Decide the rule on the user's original config, before collapse. The clean rule: keyless is only allowed when the user explicitly wrote provider: openai_compatible — i.e. they chose the self-host path. Any vendor shortcut (openai/gemini/anthropic) is cloud and requires a token. Apply the fail-fast check accordingly.

Commit: feat(config): require a token for cloud providers, allow keyless only for explicit self-host
6. Docs.

Update the docs/llm-providers.md from last turn and the README: one protocol now, vendor names are shortcuts, openai.com goes through Chat Completions. Note the shortcut-name lock-in below.

Commit: docs: document single-protocol model and vendor shortcuts
One forward-compat decision to make now
The shipped shortcut names are about to be locked to "compat" semantics. If native Anthropic ever lands, provider: anthropic will already mean "compat via Anthropic's compat endpoint" — so native would have to be a new value (e.g. anthropic_native), or you'd break existing configs by flipping the meaning. That's not wrong, just a fork to choose deliberately: either accept that vendor shortcuts permanently mean compat (native gets a distinct name), or decide now that the shortcuts are provisional. Since you've already shipped them, I'd accept the lock and reserve *_native for later — but write that intent into a comment near the shortcut map so future-you doesn't agonize over the naming collision.
Net: your three moves (separate protocol from vendor, default-URL convenience map, collapse to one client) are all correct — with one fix: the protocol discriminator stays single-valued and honest now, vendor names become sugar rather than protocol values, and the door stays open through the resolver seam you already built, not through a speculative enum.
